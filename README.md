# 太易（YI）

太易（YI）是一套面向科研与软件开发的项目初始化和长期维护配置，用来减少多轮开发中的重复实现、文档过期、规则累积和表达空泛。它包含可复制的项目约定、README 骨架及一次性初始化指令。实际项目通常只需合并前两个文件；研究报告和初始化指令留在 YI，不复制进每个项目。

研究日期：2026-11-13。CoEvo 已试点预算和文档精简；后续核验发现预算基线包含大量未暂存材料，现已在候选配置中消除额外额度，并统一查询、检查和收紧的暂存快照。长期开发效果仍待实际使用检验。

- [项目树与强制预算](structure-and-budget.md)：基于本机盘点的 Ratchet 接入与存量收缩方案。
- [CoEvo 试点复核](structure-and-budget.md#coevo-试点复核)：基线余量、提交时校验与批准边界的实测结果。
- [研究与取舍](research.md)：已有技能审查、证据、长期维护机制与验证办法。
- [项目开发约定](templates/AGENTS.md)：可复制的通用起点；已有全局偏好时去重，只保留项目差异。
- [暂存检查模板](templates/pre-commit)：检查暂存快照并与 HEAD 比较；按项目验证后安装。
- [README 骨架](templates/README.md)：填入项目真实命令和输入输出；它不是已经可运行的项目。
- [初始化指令](initialize.txt)：选定目标项目后交给 Agent 执行，按科研或软件任务补齐必要内容。
- [存量项目减负指令](retrofit.txt)：用于已经膨胀的项目，覆盖薄层、接口、防御性代码及冗余审查的删除。
- [文字处理指令](writing.txt)：去黑话、精简防御性文字、保护事实关系；按用途交付可用文本。
- [验证记录](verification.json)：本轮检查和适用范围。

使用时先合并已有内容，再验证 README 的命令，最后在新会话中核实规则确实加载。一个项目只保留一个现役约定来源。平台需要其他入口文件时使用其支持的导入或短引用，并实际验证；不要维护多份独立正文。

默认保留自主执行：新文件、合理的依赖和必要抽象属于实现判断。超过当前授权的破坏性或外部动作才需要另行确认。不设置每次新建文件的审批；按用户补充采用 Ratchet 强制增长预算，实际基线与执行位置须在选定项目中配置。

后续维护跟随改动发生：入口变化就改运行说明，接口退役就处理引用，规则失效就改原条目。只有需要跨会话继续的工作才留下当前计划，完成后保留有长期用途的结论。每个交付周期抽查一次从 README 运行、从结果追溯输入、从术语理解行为是否仍可完成。

## 开始使用

新项目使用 `initialize.txt`，已有膨胀项目使用 `retrofit.txt`。将对应指令与目标项目路径交给 Agent，按项目实际情况合并 `templates/AGENTS.md` 和 README 骨架；无需把整个 YI 仓库复制进目标项目。

撰写或精简文字时使用 `writing.txt`，并提供原文、读者和改动范围。这是按需读取的流程；YI 尚未提供通用黑话检查器或语义保真程序，Git/Ratchet 也不会判定文字质量。

使用强制预算前，先阅读 [项目树与预算方案](structure-and-budget.md)，选择统计范围并以审阅后的暂存内容建立基线。`templates/pre-commit` 是可安装的 Git hook，支持 `check`、`budget` 和 `tighten`；安装时合并已有 hook，不覆盖其他检查。

在 YI 仓库复跑提交约束测试（Python 3.10+、Git、POSIX shell）：

```sh
python3 -m venv .cache/ratchet-env
.cache/ratchet-env/bin/python -m pip install ratchet-size==0.2.3
.cache/ratchet-env/bin/python -m unittest discover -s tests -v
```

测试在临时 Git 仓库执行，不安装 hook 或修改使用者项目。`verification.json` 还包含本地写作技能和 CoEvo 的历史观察；这些外部材料未随 YI 分发，不能用上述命令复现全部历史观察。

## 参与研究

欢迎提交能复现的膨胀案例、约束绕过、误拦截和精简前后比较。说明任务、模型与工具版本、原有结构、具体修改、行为验证及时间成本；数据或代码不能公开时，提供脱敏最小案例。讨论以真实任务收益为准，行数下降本身不算成功。
