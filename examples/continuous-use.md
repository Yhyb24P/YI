# YI 自身的连续维护案例

2026-11-13，从 `0d48a9d5e973d53939ac22515ed3832e5522603f` 出发，处理实际预算接口的两项问题。执行者为当前 Codex 会话，模型为 GPT-6 Astra；使用仓库现有 Python 3.12.3、Git 和 ratchet-size 0.2.3。先添加可复现失败的测试，再修改共享实现；没有另建检查服务或引入运行时依赖。

## 第一项 分组重排会绕过范围检查

配置按第一个匹配组归类，但原实现用字典相等判断范围是否变化，忽略了组的顺序。测试建立明确的源码余量，然后增加测试内容：原顺序下测试组超限；只把 source 组移到最前面，新增测试便被算入源码组并通过。

新增 `test_group_order_cannot_move_tests_into_source_allowance` 后，旧实现返回 0，而预期为 2。修复将分组比较改为有序条目比较，沿用原有 scope SHA-256 与批准机制，没有再加另一套审批逻辑。修复后重排会被拒绝。

## 第二项 后续脚本接入不能解析报告

初始化和收紧先打印 JSON，再在同一标准输出追加提示，导致 `json.loads(stdout)` 报 `Extra data`。这影响把 YI 接入自动化时读取预算结果。

新增 `test_stdout_is_one_json_report_for_all_successful_actions`，连续调用 init、budget、check、tighten 并解析输出。修复仅将两条操作提示移到标准错误；JSON 结构、退出码及写入行为沿用现有接口。第二项修复后的完整测试仍包括第一项的绕过负例。
